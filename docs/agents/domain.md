# 领域文档（Domain Docs）

工程技能在探索代码库时，按本文件消费本仓库的领域文档。

## 探索前先读

- 仓库根 **`CONTEXT.md`**（若存在），或
- 根 **`CONTEXT-MAP.md`**（若存在）：指向每个上下文的 `CONTEXT.md`（多上下文仓库）；
- **`docs/adr/`**：读与将工作区域相关的 ADR。

若这些文件不存在，**静默继续**——不要提示缺失，也不要建议预先创建；`/domain-modeling` 会在术语或决定实际被解决时才惰性创建它们。

## 文件结构

单上下文仓库（绝大多数仓库）：

```
/
├── CONTEXT.md
├── docs/adr/
└── src/
```

多上下文仓库（根存在 `CONTEXT-MAP.md`）：每个上下文一份 `CONTEXT.md` 与上下文级 `docs/adr/`。

## 使用词汇表的术语

当输出命名领域概念（issue 标题、重构提议、假设、测试名）时，使用 `CONTEXT.md` 中定义的术语，不要漂移到词汇表明确 Avoid 的同义词。

若所需概念不在词汇表里，这是一个信号：要么你在发明项目不用的语言（重新考虑），要么存在真实的空缺（记给 `/domain-modeling`）。

## 标记 ADR 冲突

若你的输出与某条 ADR 冲突，显式指出而不是静默覆盖：

> _与 ADR-000N（…）冲突，但值得重新讨论，因为…_
